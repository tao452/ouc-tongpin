# OUC同频 · 界面设计规范

## 1. 文档说明

本文档用于规范 OUC 同频微信小程序学生端的基础视觉样式与交互表现，为后续高保真界面设计和前端开发提供统一参考。

本文档由 M2 产品与体验设计负责整理。当前规范为设计初稿，具体颜色、组件样式及页面适配方式可根据团队讨论和实际设计效果调整。

## 2. 设计目标

- **清晰易用：** 页面布局清晰，主要功能入口容易识别。
- **自然友好：** 采用轻松、友好的视觉风格，符合校园社交场景。
- **低压力社交：** 避免过度强调竞争、排名等容易增加社交压力的设计。
- **视觉一致：** 统一颜色、字体、按钮、卡片和页面间距。
- **便于开发：** 尽量使用可复用的组件和明确的尺寸规范。

## 3. 色彩规范

以下为初步建议色值，尚未经过团队确认。

| 用途 | 色彩名称 | 色值 |
|---|---|---|
| 品牌主色 | 清新蓝 | #5B8DEF |
| 品牌辅助色 | 浅蓝 | #EAF2FF |
| 页面背景 | 浅灰白 | #F7F8FA |
| 卡片背景 | 白色 | #FFFFFF |
| 主要文字 | 深灰黑 | #222831 |
| 次要文字 | 中灰色 | #667085 |
| 辅助文字 | 浅灰色 | #98A2B3 |
| 分割线与边框 | 浅灰色 | #EAECF0 |
| 成功状态 | 绿色 | #12B76A |
| 警示状态 | 橙色 | #F79009 |
| 错误状态 | 红色 | #F04438 |

使用原则：

- 主色用于主要操作按钮、选中状态及重点信息。
- 辅助色用于标签背景、提示区域和轻量级装饰。
- 正文与背景保持足够的对比度，保证文字易读。
- 成功、警示和错误颜色仅用于对应状态，不作为大面积装饰色。
- 最终色值以团队确认后的 Figma 设计稿为准。

## 4. 字体与文字层级

优先使用微信小程序及系统默认的无衬线字体，避免因设备差异导致文字显示异常。

| 文字层级 | 建议字号 | 建议字重 | 使用场景 |
|---|---|---|---|
| 页面标题 | 22 px | 加粗 | 页面主标题 |
| 模块标题 | 18 px | 加粗 | 卡片或内容模块标题 |
| 正文 | 14–16 px | 常规 | 主要说明文字 |
| 辅助文字 | 12–13 px | 常规 | 时间、补充说明 |
| 按钮文字 | 14–16 px | 中等或加粗 | 按钮、主要操作 |

说明：以上字号为设计阶段的参考值，实际使用时应结合微信小程序显示效果进行调整。

## 5. 间距与布局

页面布局优先保持统一的对齐方式和舒适的留白。

| 项目 | 建议值 | 使用场景 |
|---|---|---|
| 页面左右边距 | 16 px | 页面主要内容区域 |
| 小组件间距 | 8 px | 图标与文字、紧邻元素 |
| 常规模块间距 | 16 px | 卡片或内容模块之间 |
| 大模块间距 | 24 px | 不同功能区域之间 |
| 卡片内部边距 | 16 px | 卡片文字及内容区域 |
| 卡片圆角 | 12 px | 信息卡片 |
| 按钮圆角 | 8–12 px | 主要按钮及次要按钮 |

布局原则：

- 同一页面内，相同类型的模块保持统一间距。
- 重要操作应有明确的视觉层级。
- 页面内容较多时，应优先保证阅读和操作体验。
- 设计时需考虑不同手机屏幕尺寸及底部安全区域。

## 6. 组件规范

### 6.1 主要按钮

用于页面中的核心操作，例如开始匹配、确认操作等。

- 使用品牌主色作为背景。
- 文字清晰，与背景保持足够对比度。
- 同一页面内的主要按钮尽量保持样式统一。
- 操作完成、加载中或不可操作时，应有明确的状态反馈。

### 6.2 次要按钮

用于取消、返回或其他非主要操作。

- 优先采用浅色背景、描边或文字按钮。
- 视觉权重低于主要按钮。
- 与主要按钮之间保持清晰的层级关系。

### 6.3 信息卡片

用于展示匹配信息、功能入口或内容摘要。

- 默认使用白色背景。
- 卡片内部采用统一的边距。
- 圆角建议为 12 px。
- 重要信息优先展示，辅助信息适当弱化。
- 避免堆叠过多装饰，影响信息阅读。

### 6.4 输入框

用于填写个人资料、搜索内容或提交信息。

- 提供明确的提示文字。
- 输入内容与提示文字在颜色上保持区别。
- 对必填项、输入错误及提交结果提供清楚的反馈。
- 涉及个人信息时，应明确说明信息用途及必要性。

### 6.5 标签

用于展示兴趣、活动类型或其他分类信息。

- 使用统一的圆角、内边距和文字样式。
- 选中状态应与未选中状态明显区分。
- 标签文字应简洁，避免过长导致布局混乱。

## 7. 交互与状态规范

页面及组件应考虑以下基本状态：

- 默认状态：展示正常内容与可用操作。
- 按压状态：让用户感知操作已被触发。
- 加载状态：提示系统正在处理，避免用户重复提交。
- 空状态：在暂无内容时提供简洁说明及合理的下一步操作。
- 错误状态：说明发生的问题，并在适当情况下提供重试方式。
- 成功状态：明确反馈操作结果。

对于匹配、社交互动等功能，应尽量使用清晰、友好的反馈文案，避免让用户感到被强迫或被评价。

## 8. 隐私与安全设计

- 仅在必要时展示用户个人信息。
- 个人资料的展示范围及可见性应遵循团队确认后的产品规则。
- 涉及授权、隐私或重要操作时，应向用户说明相关影响。
- 如产品需求包含举报、屏蔽等功能，应为相关操作提供清楚的入口和反馈。
- 不在设计阶段自行确定尚未经过团队讨论的隐私策略。

## 9. Figma 文件组织建议

建议在 Figma 中按以下结构组织设计内容：

- `00_项目概览`：产品定位、设计目标和视觉方向。
- `01_信息架构与低保真`：页面关系、主要流程及低保真原型。
- `02_高保真与组件规范`：高保真页面、颜色、文字及组件样式。

页面和组件命名应尽量清晰，方便团队成员查找和复用。

## 10. 待确认事项

1. 品牌主色及整体视觉风格是否符合团队预期？
2. 学生端需要优先设计哪些页面？
3. 是否已有团队统一的图标、插画或品牌素材？
4. 按钮、卡片及导航栏是否需要形成可复用组件？
5. 不同迭代版本分别需要交付哪些设计稿？
6. 隐私、安全及异常状态需要覆盖哪些具体场景？

# OUC同频 UI 设计规范 V1

## 1. 设计原则

本项目采用温暖、简洁、友好的视觉风格，降低用户表达情绪和发布需求时的心理压力。

设计原则：
- 视觉简洁，减少不必要的信息干扰。
- 统一页面布局、字体、颜色和组件样式。
- 保持打卡、树洞、校园广场三个模块的视觉一致性。
- 对成功、空内容、错误等状态提供清晰反馈。

| 文字类型 | 字号 | 字重 |

| 页面主标题 | 21–28 px | Bold |
| 区域标题 | 14–18 px | Semibold |
| 卡片标题 | 14–16 px | Medium / Semibold |

| 辅助文字 | 11–12 px | Regular |

## 5. 间距与圆角规范

- 页面常用左右边距：20 px。
- 常用间距以 8 px 为基础进行组合。
- 卡片常用圆角：14 px。
- 按钮常用圆角：14 px。
- 输入框常用圆角：12 px。
- 分类标签采用胶囊形圆角。
- 页面卡片优先使用白色背景和浅色边框。

- 背景色：#789477。

### 6.2 Secondary Button（次按钮）

- 高度：48 px。
- 圆角：14 px。

- 字号：16 px。

### 6.4 Input Field（输入框）

- 单行高度：44 px。

- 圆角：12 px。
- 背景色：#FFFFFF。

- 错误状态边框：#D98B7B。

### 6.5 Content Card（内容卡片）

- 边框颜色：#EAE9E2。

## 8. 页面与布局规范

- 页面统一采用 375 × 812 px 画板。
- 页面背景统一使用 #F8F7F3。
- 常用页面左右边距为 20 px。
- 页面底部操作区域保持统一的视觉样式。
- 内容卡片、按钮、标签优先使用组件库中的标准组件。
- 不同业务模块保持一致的字体、色彩和间距体系。

## 9. 待确认事项

以下内容需要与项目相关成员进一步确认，不作为已经确定的业务规则：

- 树洞内容及需求标题的最大字数。
- 各输入字段的必填、选填和长度限制。
- 输入内容的格式校验规则。
- 匿名发布的具体业务逻辑。
- 校园需求发布后的匹配流程及匹配成功条件。
- 暂无匹配结果时的页面状态。
