## 3 一个故事从认领到完成（六步）

1. **认领**：在 Projects 看板把 Issue 拖到 In Progress，评论 `@me 认领`。
2. **建分支**（≤3 天生命周期）：
   ```bash
   git switch develop && git pull --rebase
   git switch -c feature/US-01-emotion-checkin
   ```
3. **查契约**：去 `packages/contract/openapi.yaml`（或 Apifox）确认接口字段。
   契约没有 → 在 Issue 里 @M5 催；后端未就绪 → 前端按契约 **Mock 先行**，不等。
4. **编码**：按 §2.2 的目录放文件；提交前本地能编译、能启动。
5. **自测**：单测通过 + Apifox 用例跑通 + 真机/页面实际操作一遍。
6. **提交与 PR**：
   ```bash
   git add -p && git commit -m "feat(mp): 情绪打卡页 (#2)"
   git fetch origin && git rebase origin/develop
   git push -u origin feature/US-01-emotion-checkin
   ```
   PR：Base `develop`，标题 `[US-01] 情绪打卡`，描述四段 = `Closes #2` / 改了什么 / 怎么自测 / 影响面与回滚。
   CI 绿 + 非作者评审 → **Squash and merge** → 删分支。

> type：`feat` `fix` `refactor` `test` `docs` `style` `perf` `chore`
> scope：`mp` `admin` `api` `algo` `docs` `infra`

## 3.1 团队同步节奏（本组裁剪版，重要）

学生团队时间有限，**不开每日站会**。进度靠「看板异步更新」+「每周 1 次例会」：

- **异步（每天发生，不开会）**：开始干活时把 Issue 在 Projects 看板从 Backlog 拖到 **In Progress**；做完拖到 **Done**；卡住就在 Issue 评论一句。组长打开看板即可看出谁动没动，博客素材自动攒下。
- **每周例会（30–45 分钟，1 次/周）**：用于同步进度、解决卡点、并拍一张「例会照片」——这张照片就是 Scrum 博客要求的 `例会照片`。
- **博客节奏**：按原要求，**每个迭代结束各发 1 篇 Scrum Meeting 博客**（W2 末、W3 末）。内容 = 每人工作 + 燃尽图 + 例会照片 + 每人代码/文档签入记录（对应 Issue 链接）。这些素材都能从看板与 `gh` 自动提取，不用开会汇报。

> 详见 `docs/team/standup/周例会记录模板.md` 与 `docs/team/blog/` 下的博客骨架。

## 4 接口契约 v0.1（S1 覆盖，草案待 M5 评审）

完整字段见 `packages/contract/openapi.yaml`。S1 核心接口清单：

| 方法 | 路径 | 用途 | 关联故事 | 主责 |
|---|---|---|---|---|
| POST | `/api/auth/login` | wx.login → code2session → JWT | US-33 | M5 |
| POST | `/api/auth/student-verify` | 学号认证、重复绑定校验 | US-33 | M5 |
| GET | `/api/emotions/words` | 情绪词表（6 词 × 1–5 强度） | US-01 | M5 |
| POST | `/api/emotions/checkins` | 打卡（**幂等**：同日重复提交只记一次） | US-01 | M5 |
| GET | `/api/emotions/checkins` | 打卡记录（日历、连续天数） | US-02/03 | M5 |
| POST | `/api/treehole/posts` | 树洞发布（匿名/实名切换） | US-05 | M5 |
| GET | `/api/treehole/posts` | 树洞列表（按情绪标签） | US-05 | M5 |
| — | 定时任务 | 24h 焚毁：Redis ZSet + 定时扫描 + 软删除 | US-07 | M5 |
| POST | `/api/moderation/check` | 敏感词 DFA + 变体归一化 | US-24 | M6 |
| POST | `/api/match/needs` | 搭子需求（场景/时间/地点/标签/距离） | US-10 | M5 |
| PUT | `/api/user/profile` | 个人资料 + user_tag 关联表 | US-35 | M1 |

**关键实现要点（方案已定，别自己发挥）**
- 打卡**幂等**；断签归零连续天数；强度 1–5；备注可选。
- 树洞焚毁：到期列表与详情**均不可见**，库里只留内容哈希用于审计。
- 匿名：US-25 匿名 ID 生成 + 日志脱敏 + 最小必要采集。
- 学号认证：学校无统一认证接口 → 抽象为 `AuthProvider`，先用「学号 + 教务截图审核」过渡。
- 敏感词：DFA + 变体归一化 + 分级词库。

## 6 每个故事"做完"的标准（DoD）

- [ ] 代码在正确目录，本地能编译、能启动
- [ ] 单测通过；涉及接口的同时有 Apifox 用例
- [ ] 真机/页面实际操作走通主流程（不是只看代码）
- [ ] 提交信息 `type(scope): subject (#Issue)`，一次提交一件事、≤200 行
- [ ] PR 含 `Closes #xx` + 四段描述，CI 绿，非作者评审通过
- [ ] Issue 上贴了**证据截图/录屏**（博客要用：燃尽图、例会照片、签入记录都靠它）
- [ ] 涉及接口的，`openapi.yaml` 同步更新（契约先行，实现在后）

## 7 常见坑

- **别直推 develop/main**，别 force push 共享分支（自己的分支用 `--force-with-lease`）。
- **别提交** `.env`、密钥、`node_modules`、`target`、大文件（CI 有 guard 会拦）。
- **不自审自合**；feature 分支不超 3 天。
- 改到别人目录 → CODEOWNERS 会自动请求该责任人评审，别绕过。
- 契约没合并前，**前端用 Mock**，不要等后端。
