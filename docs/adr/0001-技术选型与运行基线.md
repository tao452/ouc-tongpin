# 技术选型与运行基线 v1

日期：2026-11-02。维护人：M6。基线为仓库 develop 已合入的实现，适用于第一迭代。
本文记录技术选择、替代方案、运行版本和验证方式；会议参与人及会议结论由实际评审记录补充。

## 系统边界

学生端使用微信小程序，管理端使用 Vue；业务数据和认证归 Spring Boot，文本过滤归 FastAPI。
两项服务分别构建和测试，Nginx 提供统一 API 入口。
沿用 ADR-0000 的单仓库多模块结构，接口唯一事实源为 `packages/contract/openapi.yaml`。

| 模块 | 采用方案 | 选择原因 | 比较与取舍 |
|---|---|---|---|
| 学生端 | 微信原生小程序、TDesign | 对接微信登录与订阅消息；复用组件 | 跨端框架会增加当前团队的适配和调试成本 |
| 管理端 | Vue 3、Vite、Element Plus、ECharts | 现有成员已采用，适合表格、审核和看板 | 手写全部组件会扩大样式和交互维护范围 |
| 主后端 | Java 17、Spring Boot 3.2、Maven、MyBatis-Plus | 统一业务、校验、数据访问和构建 | Node/Python 单后端会改变既定分工及已有代码 |
| 数据 | MySQL 8、Redis 7 | 关系数据、唯一约束与临时状态分别处理 | 内存存储只用于当前接口骨架，不承担持久化 |
| 算法服务 | Python 3.11、FastAPI、Pytest | 独立迭代、接口校验、与离线脚本共用逻辑 | 直接嵌入 Java 增加文本处理与实验维护成本 |
| 文本过滤 | DFA 前缀树、OpenCC、显式谐音别名、完整拼音段 | 本地执行，规则及结果可复现 | 全量同音转换会扩大误判，正则组合较难管理词库 |
| 接口协作 | OpenAPI 3.1、Apifox 导入 | 字段、示例和错误码可被前后端共用 | 只在群聊约定字段容易造成版本偏差 |
| 环境 | Docker Compose v2、Nginx | 新环境能按相同拓扑构建和验证 | 手动装五个服务增加端口、版本和密码差异 |
| 质量与发布 | GitHub Actions、Ruff、Pytest、Maven verify | 每个 PR 执行检查，保留运行及产物记录 | 只依赖本地检查难以复现成员间的环境问题 |

## 运行版本

- Java 17 是主后端、Dockerfile 和 CI 的共同基线。使用 Java 21 的工作分支先调整兼容性再集成。
- Python 3.11 用于镜像与 CI；开发机 Python 3.12.14 已有测试记录。
- Node 22 用于管理端镜像与发布包构建；管理端独立 CI 同步使用 Node 22。
- Python 依赖版本在 requirements 文件固定；Java、前端依赖分别由 pom.xml 和 package-lock.json 管理。
- MySQL 本机映射 3307、统一入口默认 8080，容器内部按服务名连接。

## 验证和变更

PR 检查包括提交规范、模块测试、镜像构建、临时测试环境和发布候选包验证。
服务调用失败时保留明确错误，内容审核超时或响应异常返回 503，禁止继续写入正文。
技术版本或接口变更先更新契约、运行配置和相关测试，再通过 PR 集成。
本轮测试环境为 GitHub 临时运行机器，验证后清理；长期测试站点另按服务器交付清单配置。

## 评审议程

评审逐项检查版本基线、接口边界、隐私数据流、失败处理、测试结果和部署条件。
记录采用 `docs/team/standup/周例会记录模板.md`，关联对应 PR、参与人、时间和具体结论。
当前可直接评审的材料包括本 ADR、情绪词库 v1、PoC 报告及四条工作流的运行结果。
