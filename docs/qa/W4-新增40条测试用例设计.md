## S1-081 重复 Authorization 头拒绝歧义身份

状态：PASS；优先级：P0；依据：CODE_REGRESSION；就绪：IMPLEMENTED_AND_EXECUTED。

目的：防止网关与 Java 对第一/最后一个身份头取值不一致。

前置条件：

- ENV：全新隔离环境并核对源 Commit
- ACTORS：A/B 均存在且 token 有效
- A/B 的同日打卡分别含私有备注 A-only/B-only

输入：

```json
{
  "route": "GET /api/emotions/checkins",
  "headers_matrix": [
    [
      "Bearer ${TA}",
      "Bearer ${TB}"
    ],
    [
      "Bearer ${TB}",
      "Bearer ${TA}"
    ]
  ]
}
```

执行步骤：

1. 分别单头请求 A/B，确认 200 正控制
2. 使用保留重复头的客户端，按两种顺序分别请求 web:80 与 api:8080
3. 比较响应正文及 A/B 的限定行快照

预期结果：

- Java 直连重复头一律 401；网关可在协议层返回 400 或转交 Java 返回 401，均不得 2xx
- 拒绝响应不含任一私有备注/凭据；数据库无新增或改写

自动化方案：在专属网络 probe 容器用 http.client.putheader 连续写两个 Authorization，禁止用会折叠重复键的 dict/requests headers；参数化两种次序和两个入口。
执行层级：`REAL_HTTP_MYSQL_REDIS`；实现：`scripts/qa/w4_new40/http_cases.py`。逐项实测证据：`docs/qa/evidence/w4-additional-40/20261122/results.json#S1-081`。

```json

    4096,
    4097
  ],
  "authorization_header_lengths": [
    4103,
    4104
  ],

  "claims": "合法 sub/iss/aud/iat/exp + 无权限含义的 padding"
```
