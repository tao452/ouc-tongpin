本轮执行现有接口与可独立验证的高优先级场景，使用 CI 创建并回收的 MySQL/Redis/Java/FastAPI 环境。

## 测试计划

80 条目录逐项分配优先级与执行方式。P0 覆盖输入边界、持久化、幂等、内容阻断、匿名响应、
超时、过期内容、隐私工具及基础设施；P1 覆盖情绪正常值、日期查询、分页与连续打卡产品规则。
执行器要求 HTTP 结果、Java 隐私 JUnit 与容器环境报告合计覆盖全部 80 个唯一 ID。

| 范围 | 本轮执行方式 | 仍需外部依赖的项目 |
|---|---|---|

所有失败保留 FAIL，未实现/未批准项目保留 BLOCKED；不放宽原接口断言，也不填造人工审批。

## 发现并修复的缺陷

- 补齐打卡 emotion 枚举、intensity 1–5、note ≤100 校验；拒绝非法查询日期与反向区间。
- 空白/非法 JSON 返回 400，未知路由返回 404，系统错误返回 500，均不回显输入或内部异常。
- 新建数据库以 `(user_id, checkin_date)` 唯一约束保障并发幂等；插入失败且找不到已有记录时抛错。
- 树洞情绪标签执行契约枚举校验；发布与列表共用安全 DTO，公开响应不包含内部身份/数据库标志。
- 匿名马甲接入已有 HMAC 工具；实名响应只取昵称。控制器仍为 demo 用户 1，不宣称已实现可信身份。
- 使用北京时间生成创建/到期时间，Redis 截止时间对应真实 24 小时；列表查询主动排除已到期内容。
- 分页增加 ID 次排序，防止相同创建时间下记录重复或遗漏。
- 未绑定学号的模拟账户返回 `needStudentVerify=true`，真实校内认证仍未实现。
