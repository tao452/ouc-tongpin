## 匿名与日志脱敏

HMAC-SHA256 别名沿用 `anon_v1_` 规则，通过服务端密钥与场景隔离。同一用户同一场景稳定，
不同用户和场景隔离；密钥缺失或过短时失败，不回退到普通哈希。

新库 `treehole_post` 不含内部 user_id，身份关联只写入私有 `treehole_identity`。
两表写入在同一数据库事务内；身份映射或 Redis 调用失败时，数据库写入回滚。
匿名读取不查询身份映射，实名响应只展示昵称，私有实体不能输出身份字段到 JSON 或日志。

焚毁任务逐帖锁行并使用事务，归档内容哈希、清正文、删除身份映射、将旧别名改为统一的
`burned` 标记后，才确认 Redis 队列。数据库失败保留重试项，Redis 确认失败后重跑不重复归档。
实际 MySQL 运行中观察到已焚毁帖子和哈希留档各 1 条，已焚毁身份映射和可关联别名均为 0。

Logback 控制台保护覆盖格式化参数与异常堆栈，补齐 access/refresh token、session key、openid、
API key、client secret 和具名学号等常见字段。引用值改为迭代字符扫描，修复 5 KB 以上凭据
引发递归正则栈溢出的问题，并验证 5 KB、20 KB、转义引号和未闭合值。
规则无法代替调用方避免记录请求正文，也不覆盖任意姓名、地址和自由文本隐私。

实现与升级交接见 [`PRIVACY.md`](../../services/api-server/PRIVACY.md)。已有库使用
[`身份分表迁移`](../../infra/db/migrations/20261115-treehole-identity-separation.sql)，
须由 M5 备份、停写后在明确授权的数据库执行。隔离 MySQL 8 的 7 项演练全部通过，
包括活动记录迁移、旧焚毁关联清理、幂等重跑、缺失/旧格式/冲突拒绝、最终 DDL 失败保留数据并重试。

## 独立 30 条接口自动化

入口为 [`run_w3_api_regression.py`](../../scripts/qa/run_w3_api_regression.py)，版本化清单为
[`w3-api-cases.v1.json`](data/w3-api-cases.v1.json)。每条有唯一 ID、业务预期、执行状态和观察记录，
缺条、重复或没有观察的 PASS 都会被拒绝。退出码 0 为全部通过，1 为用例失败，2 为输入或输出错误。

| 模块 | 条数 | 验证内容 | 本次结果 |
|---|---:|---|---|
| 登录 | 6 | 模拟首次/重复登录、缺少/空白/null code、畸形 JSON、实际建档与不重复写入 | 6 PASS |
| 打卡 | 14 | 六情绪、强度边界、必填项、备注长度、同日幂等、日期区间、非法日期、八请求并发幂等 | 14 PASS |
| 树洞 | 10 | 默认/显式匿名、稳定马甲、实名昵称、HIGH 阻断、长度与必填项、筛选、分页隐私 | 10 PASS |

成功写入会核对 MySQL 实际字段与 Redis 具体队列成员，失败输入检查未写入。
报告不保存 token、用户 ID、匿名 ID、正文或完整响应；响应中的统计字段只接受规定类型，
命中等级只接受固定枚举，截断的 HTTP 响应计 FAIL 并继续执行。
执行前拒绝报告覆盖清单、源码、契约、环境文件或 Compose 配置。

在已经建立的可回收隔离栈中，从仓库根目录运行：

```powershell
python scripts/qa/run_w3_api_regression.py --output qa-private/w3-api-regression.json --allow-disposable-stack
python scripts/qa/run_w3_load.py --output qa-private/w3-load.json
python scripts/qa/run_pii_baseline.py --output qa-private/pii-baseline.json
```

自建栈可另传 `--env-file`、重复 `--compose-file`、`--project-name` 和 `--base-url`，
必须对应同一个隔离环境。脚本会创建合成账户、打卡和帖子，按随机未来日期避开旧回归数据，
应串行运行，不指向共享环境。登录仍使用现有 code2session 模拟，业务接口仍为 demo 用户 1。

`.github/workflows/deploy-test.yml` 已接入 30 条回归、只读并发演示和报告上传。
下表记录推送前的本地验证；工作流已通过 actionlint 静态检查，提交后的 GitHub Actions 结果以 PR 检查为准。

返回 2 且不回显原文或路径。交接范围、实际业务输入格式和人工复核模板见
[`PII 基线说明`](pii-baseline/README.md)。M1 确认范围后，由 M5 提供受限测试导出和日志，
