## 实际容器与HTTP

`scripts/ci/create-test-env.py`会生成当前目录的`.env`，仅在全新测试目录、确认没有原有`.env`后使用。所有密钥保留在本地。给每次测试设置不同的`COMPOSE_PROJECT_NAME`，选择空闲端口；Compose文件同时使用：

```sh
python scripts/ci/create-test-env.py
export COMPOSE_PROJECT_NAME=ouc-us12-m3-unique
docker compose --env-file .env -f infra/docker-compose.yml -f infra/docker-compose.us12-test.yml up -d --build --wait --wait-timeout 240
python scripts/qa/verify_match_service.py --output qa-private/us12-independent-http.json
MATCH_DOCKER_URL=http://127.0.0.1:18000 mvn -f services/api-server/pom.xml -B -q -Dtest=MatchingScoreDockerIT test
python services/algo/scripts/evaluate_match.py --base-url http://127.0.0.1:18000 --output qa-private/us12-independent-evaluation-http.json
```

网关默认8080、内部评分测试端口18000；HTTP脚本支持`--gateway-url/--base-url`，端口改动时一起修改。Windows PowerShell用`$env:变量名=...`设置环境变量。测试端口只绑定127.0.0.1；公开网关POST /score必须404，算法容器直接调用200。

SQL结构仅在自己的临时数据库中应用[schema-proposal.sql](../../services/algo/match/schema-proposal.sql)。检查版本/哈希、JSON数值特征、0～100分数范围、重复唯一键；不得给公开reader授权画像或快照表。当前M6实测5000行快照记录见SQL证据。
