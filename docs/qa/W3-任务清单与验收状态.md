## 统一质量报告

`scripts/qa/report_w3_delivery.py` 汇总同一提交的四份实际运行报告：

```powershell
python scripts/qa/report_w3_delivery.py `
  --api-report qa-private/w3-api-regression.json `
  --pii-report qa-private/pii-baseline.json `
  --load-report qa-private/w3-load.json `
  --java-report qa-private/regression-java.json `
  --output qa-private/w3-delivery.json
```

默认按当前 HEAD 核对；复核归档证据时，用 `--expected-revision` 显式指定完整的被测提交。
对应 Git 对象必须已存在本地。CI PR 运行使用 GitHub 生成的合并测试提交，报告中的 revision
可能与 PR head 不同；同次运行的四份证据必须一致，不能混用不同版本。

程序核对 Git 中的脚本／清单／语料字节哈希，重新统计 30 个唯一接口 ID、62 个 PII 预期、
7 项隐私 JUnit 和全部并发请求。缺项、重复、失败、计数或耗时汇总不一致均返回 1。
报告仅输出计数、版本、时间和哈希，保留输入报告的 dirty 标志，不复制响应、身份、凭据或原文。
输出限定在忽略目录且不能覆盖输入。成功退出表示自动化验证通过，`business_acceptance`
仍为 false；PII 的 6 条已知能力缺口也继续列出。

CI 在 Java、算法与全栈任务均执行成功时生成 `w3-delivery-evidence` artifact。
当两端代码检查均被选中时，现有 `quality` 门禁强制要求这份统一报告通过。
其他目录的独立变更仍沿用对应模块检查。
