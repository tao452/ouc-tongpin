## 一、三条决策

| 待定问题 | 决定 | 理由 |
|---|---|---|
| 自然周 / 自然月 还是滚动窗口 | **滚动窗口**：「近 7 天」= 含今天往前数 7 天，「近 30 天」= 含今天往前数 30 天。页面文案写「近 7 天 / 近 30 天」，不写「本周 / 本月」 | 点数固定，两套视图共用一套逻辑；不会出现「本周才过 2 天」或「月初只有 1 个点」的半空图；跨月 / 跨年无需特殊处理 |
| 分布按次数还是天数 | **按有效打卡记录条数计占比**，分母 = 区间内有打卡的记录总数；**未打卡日不进分母**，另单独显示「N 天未打卡」 | 后端同日幂等，一天最多一条，次数与天数数值本来相同；「没打卡」不是一种情绪，计入分母会稀释占比并误导解读 |
| 断签留空还是补 0 | **折线留空断开，不补 0**；断点用空心点 / 虚线表示，并标注未打卡天数 | 合法强度是 1–5，补 0 会把「没记录」画成「情绪极低」的假低谷，属于数据失真 |

补充：曲线取**当日唯一一条记录的 `intensity`**，不做平均（幂等保证一天最多一条）。

## 二、数据源与实现约束

1. 只调现成的 `GET /api/emotions/checkins?from=<窗口首日>&to=<今天>`，**前端本地聚合，不新增后端接口、不改 `openapi.yaml`**。
2. 响应字段：`items[].checkinDate / emotion / intensity`；`streakDays` 是全局连续天数、`total` 是区间内条数，两者都不要当成本窗口的统计结果。
3. 日期用 `new Date()` 减 `N-1` 天算首日，格式化 `YYYY-MM-DD`；**`to` 恒为今天，永远合法**，不要手拼月末日期（日历页 `2026-11-31` → 后端 400 的坑不要重演）。
4. 6 种情绪按 `utils/checkin.js` 的固定顺序与颜色展示：`HAPPY / CALM / ANXIOUS / LONELY / IRRITABLE / DOWN`，**不按占比动态排序**，避免颜色和顺序跳变。
5. 聚合逻辑抽成纯函数模块 + 单测（照 `utils/calendar.js` / `utils/treehole.js` 写法）；图表用手写 view / canvas，**不引入 echarts 或新 npm 组件**（`miniprogram_npm/` 需构建，已踩过编译失败）。
6. 与打卡日历**有意不同**：日历按自然月（`getMonthRange`）展示，曲线按滚动窗口统计，两套口径不要互相复用函数。

## 三、边界与空态

| 场景 | 要求 |
|---|---|
| 区间内 0 条记录 | 显示「还没有打卡记录」，不画 0 值折线、不显示 0% 分布图 |
| 只有 1 条记录 | 折线画单点、分布该项 100%，其余显示 0%（不画空柱） |
| 中间断签 | 折线断开，显示「N 天未打卡」，不出现强度 0 的点 |
| 全部同一情绪 | 分布 100% 正常显示，不除零、不 NaN |
| 请求失败 / 响应异常 | 显示错误态 + 重试按钮，不白屏、不报 500、不静默当成 0 条 |
| 强度边界 1 / 5 | 正常渲染，纵轴刻度固定 1–5，不自动缩放到 0 |

## 五、可直接贴到 #4 的 DoR 第 4 条评论

> **业务口径（M1 确认，2026-11-14）**：US-03 的「近一周 / 近一月」定义为**滚动窗口**，近 7 天 / 近 30 天均含今天；情绪分布按区间内**有效打卡记录条数**计占比，未打卡日不进分母，单独显示未打卡天数；强度折线在断签日**留空断开、不补 0**（强度合法范围 1–5），曲线取当日唯一记录值不做平均。数据源为 `GET /api/emotions/checkins?from&to` 前端本地聚合，不新增接口。空态、单条、全同一情绪、请求失败四类边界须有明确表现。详细口径见 `docs/requirements/情绪曲线与分布-验收口径-v1.md`。
