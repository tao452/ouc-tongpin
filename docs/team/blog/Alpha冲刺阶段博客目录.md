## 三、习得的软工原理 / 方法 / 技能

> 结合《软件工程导论》（第六版）课程学习，以及 Alpha 冲刺（10/21 – 11/15）从需求分析到测试交付的完整实践，把学到的软件工程知识整理为原理、方法、技能三部分。

### 原理：

1. **软件工程与软件危机**：软件开发不能靠个人经验和临时发挥，必须用工程化的方法、过程和工具来管理需求、设计、实现与维护，才能应对变化、控制质量与进度。
2. **软件生命周期与过程模型**：软件要经历可行性研究、需求分析、总体设计与详细设计、编码、测试、运行维护等阶段；我们采用增量、迭代的过程，每个冲刺交付可运行的成果，而不是等到最后一次性集成。
3. **需求分析与规格说明**：需求分功能需求与非功能需求，要用用户故事和验收标准把它描述清楚、可验证；需求变更须走控制流程，不能口头说改就改。
4. **模块化与信息隐藏**：系统按模块 / 服务划分，模块之间通过明确的接口通信（高内聚、低耦合），内部实现的变化不影响其他部分；先定义好接口契约，再让各部分并行开发。
5. **软件质量与质量保证**：质量不是最后靠测试「测出来」的，正确性、健壮性、可维护性与安全性要在需求、设计、编码各阶段逐步落实；同时如实区分「已实现 / 已验证 / 已验收」，不能把已实现说成已验收。

### 方法：

1. **需求分析方法**：用用例 / 用户故事描述功能需求，用 E-R 图、数据字典描述数据需求，先建模并评审，再进入设计与实现。
2. **设计与建模方法**：先做总体设计（划分模块、定义接口），再做详细设计；用接口契约固定模块边界，使前后端按同一份契约并行开发。
3. **软件测试策略**：测试分单元测试、集成测试、系统测试和验收测试；黑盒测试按规格验证功能，白盒测试按结构设计覆盖，由小到大逐步集成，先发现局部问题再验证整体。
4. **项目管理与配置管理**：把工作拆成可估算、可跟踪的任务，用看板 / 燃尽图跟踪进度；代码与文档纳入版本管理，每次变更可追踪、可回退。
5. **技术评审与质量保证**：通过同行评审尽早发现缺陷，评审意见要写清验证了什么、哪些还没验证；过程中的例外情况要留存记录，不能笼统写成「已通过」。

### 技能：

1. **需求建模**：能编写用户故事与验收标准，绘制 E-R 图、数据流图，编制数据字典。
2. **接口与契约设计**：能定义 API 契约、编写接口规格说明，使不同模块按同一份契约协作。
3. **编码与调试**：按编码规范实现功能，使用调试工具与静态检查定位并修复问题。
4. **测试实施**：能设计测试用例，实施单元、集成与系统测试，编写测试报告。
5. **版本控制与文档编写**：用 Git 管理代码与文档的版本，编写需求规格说明书、设计说明书、测试报告等软件文档。
