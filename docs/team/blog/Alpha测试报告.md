## 五、场景测试

### 场景 1：情绪打卡

- **典型用户**：阿同，大二学生，近期备考焦虑，想用打卡记录情绪变化。
- **需求**：每天用 1–5 分记录情绪强度并备注，周末看一周曲线。
- **场景描述**：
  1. 阿同打开微信小程序，点击首页"情绪打卡"，选择今日情绪词（如"焦虑"）并拖动强度到 4 分，填写备注"模考压力大"。
  2. 提交后，日历页对应日期显示打卡标记，连续打卡天数 +1。
  3. 阿同点击"情绪曲线"，查看近一周强度折线图与分布，发现周三最低、周末回升。
- **当前状态**：步骤 1–2 的日历与后端 checkins 接口已在 US-02（PR#41）实现；微信登录与曲线图（#4）待 M3 在 S2 联调。
- **未验证项**：真实登录态、数据库落库、连续天数计算。

### 场景 2：寻找搭子（计划）

- **典型用户**：小普，想找同校同学一起夜跑。
- **需求**：发布搭子需求，按标签匹配，匹配成功后可在树洞/私信沟通。
- **场景描述**：发布"今晚 8 点操场夜跑，配速 6'00''" → 系统按运动标签推荐 3 位同校用户 → 对方接受后建立会话。
- **当前状态**：US-10（#11）已派 M3，页面未开工，匹配逻辑待 S2；本轮仅完成接口占位设计。

### 场景 3：发布前的敏感词阻断（能力已具备，业务未接入）

- **典型用户**：小同，想在树洞发一条情绪宣泄，但内容包含人身攻击。
- **预期链路**：提交 → Java 调 `ModerationClient.requireAllowed(text)` → 算法返回 HIGH → 接口 422 → 不写库；算法不可用时返回 503，同样不写库。
- **当前状态**：算法服务（分级拦截、变体归一化、16KiB 边界）与 Java 客户端（失败关闭）已在 PR#49 合入并验证；**树洞/搭子的发布接口尚未接入**，因此尚无真实写库链路可验收。

3. 80 条手工用例、30 条业务接口自动化、并发压测与监控未完成，列入 S2/S3。
