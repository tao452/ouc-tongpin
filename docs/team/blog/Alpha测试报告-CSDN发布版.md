## 三、80 条跨模块用例执行结果

以 80 条 `s1-test-cases.json` 目录为业务验收口径，在隔离的 Linux Compose 全栈（真实 MySQL / Redis）执行。**最终结果：63 PASS / 17 BLOCKED / 0 FAIL / 0 NOT_RUN**（P0 52 PASS / 16 BLOCKED，P1 11 PASS / 1 BLOCKED）。

| 模块              | PASS   | BLOCKED | 主要阻塞原因                                |
| --------------- | ------:| -------:| ------------------------------------- |
| 登录认证 auth       | 1      | 11      | 真实微信 code2session（5）、校内认证 / 截图授权接口（6） |
| 打卡 checkin      | 17     | 1       | 连续 / 断签最终产品口径待定                       |
| 树洞 treehole     | 15     | 1       | 树洞详情接口未实装                             |
| 搭子需求 needs      | 8      | 0       | —                                     |
| 内容过滤 moderation | 12     | 2       | LOW / MEDIUM 正式词库与等级口径待定              |
| 隐私 privacy      | 7      | 1       | JWT 调用者身份与身份映射授权未接                    |
| 容器与门禁 infra     | 3      | 1       | 分支保护管理员证明待补                           |
| **合计**          | **63** | **17**  | —                                     |

- **17 条 BLOCKED 的构成**：真实微信授权 5、学号认证 / 截图授权 6、正式词库等级 2、树洞详情 1、JWT 身份 1、连续 / 断签产品口径 1、分支保护管理员证明 1；对应 #25 / #26、JWT 与 ER 图等仍未验收。BLOCKED 是先补接口 / 数据 / 规则再测，不是通过，也不是失败。
- **口径说明**：80 条目录的历史归档快照为 55 PASS / 25 BLOCKED（11/09），后续因搭子需求接口实装，S1-047~054 八条转 PASS，得出上表的 63 / 17（11/14 执行、11/15 复跑一致）。另有 9 条非 S1 补充回归全 PASS，CI 文件 `status_counts` 的 62 PASS / 17 BLOCKED 是含这 9 条的另一种计数，不是 80 条目录的 PASS 数，不与 55 / 63 混用。归档快照与最终结果按双轨文档纪律各自保留，不回改历史。
- **已修复并验证的缺陷**：打卡参数枚举 / 强度 1–5 / 备注 ≤100 校验、非法查询日期、唯一索引 `(user_id, checkin_date)` 并发幂等、树洞标签枚举与安全 DTO、北京时间到期与列表排除、分页 ID 次排序。

## 五、场景测试

### 场景 1：情绪打卡（已实测闭环）

- **用户与场景**：学生每天记录情绪与强度、查看一周变化。首页进入打卡 → 选择情绪词与 1–5 强度、填备注 → 提交 → 记录页 / 日历出现标记、连续天数 +1；可切换近 7 天 / 30 天曲线与情绪分布。
- **验证结果**：词表接口返回结构正确；打卡提交成功，真实 MySQL `checkin` 表落库、`streakDays` 与返回一致；首页状态回填、日历月末问题已修复；曲线 / 分布按验收口径 v1 实现并通过单测。
- **边界**：登录为 mock，请求共用 demo `userId=1L`；情绪曲线已由 M1 拍板关单、B16 已修复，但 M4 独立复核、QA 用例登记与截图 / 录屏仍缺（流程例外，见第七节）；曲线复用现成接口，未新增后端接口。

### 场景 2：树洞发布与 24h 焚毁（前后端已接，详情 / 到期仍未验）

- **用户与场景**：用户匿名发布情绪宣泄，24 小时后不再被检索。
- **验证结果**：发布前调用内容审核，HIGH → 422 / 服务不可用 → 503 均不写库；列表排除到期内容、北京时间到期与 Redis 截止时间一致；小程序树洞页已接发布 / 筛选 / 分页与错误分支，主页入口已接通。
- **边界**：树洞详情接口未实装（S1-045 仍 BLOCKED）；24h 到期的端到端时间加速验证未完成。

### 场景 3：发布前敏感词阻断（六场景通过，正式词库待验收）

- **链路**：提交 → Java 审核客户端 → 算法返回 HIGH → 422 不写库；算法不可用 → 503 不写库。
- **验证结果**：六场景容器回归通过；300 条合成样本误杀 0/200、检出 100/100；搭子需求发布复用同一「写库前审核」，HIGH→422、停算法→503 均不落库。
- **边界**：这是示例词库 + 自编合成文本的开发回归；正式词库、词条等级、独立标注集与完整业务验收仍在 #25（OPEN），LOW / MEDIUM 两条用例保持 BLOCKED。

### 场景 4：寻找搭子（发布链路已打通，#11 已关单但复核仍缺）

- **场景**：发布一条活动需求 → 按标签推荐同校用户 → 建立会话。
- **验证结果**：`POST /api/match/needs` 已实装（201、落库、写库前审核），广场发布页按契约真实调用；需求发布相关用例全部转 PASS，八条 needs 用例由 BLOCKED 转 PASS。

## 七、结论与遗留

1. **交付结论**：Alpha 按「工程就绪 + 契约先行 + 一个端到端可演示闭环 + 诚实证据链」交付；未承诺完整业务闭环、未完成 M4 独立复核，也未上架微信小程序。
2. **测试数字口径**：以 80 条目录为准，最终结果 **63 PASS / 17 BLOCKED**（历史归档快照 55 / 25，按双轨纪律各自保留）；`status_counts` 的 62 / 17 是含 9 条补充回归的另一种计数；自动化与合成样本另行列示。BLOCKED ≠ PASS，0 FAIL ≠ 全过，CI 绿 ≠ 业务验收，不外推为「全部通过」。
3. **未完成遗留**：JWT 真实平台验证与多用户隔离、ER 图与契约全部实装、M4 补做 #4 / #11 独立复核并勾选 DoR 第 5 条、QA 用例登记与截图 / 录屏补交、正式词库 #25 验收、真实业务 PII 验收 #26、树洞详情与 24h 到期端到端、管理端路由与真实接口、`v0.1.0` tag / GitHub Release、M6 用新证据重生成用例目录。
4. **流程例外**：部分 PR 由组长以 `--admin` 在无非作者审批下合入 develop；#4 / #11 由组长拍板关单，DoR 第 5 条「M4 独立复核」保持未勾。因此关单是「组长拍板收口」，不是「独立复核通过」。
