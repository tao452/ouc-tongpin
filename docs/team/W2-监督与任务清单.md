## 四、监督清单（组长每日/每周核对）

**每周例会（30–45 分钟，1 次/周）核对：**
- [ ] 6 人各说：本周做了啥 / 下周计划 / 卡点（不用每天开会，卡点随时在 Issue 评论里升级）
- [ ] 卡点超 2 天未升级的，当场点名
- [ ] 燃尽图 +1 个真实数据点（或会后由组长从看板自动生成）
- [ ] 例会照片拍 1 张，命名 `YYYY-MM-DD-standup.jpg` 入 `docs/team/photos/`
- [ ] 例会记录写入 `docs/team/standup/YYYY-Wxx.md`

**异步进度（每天发生，不开会）：** 每人开始/结束干活时把 Issue 在 Projects 看板拖一下（Backlog → In Progress → Done），卡住就在 Issue 评论一句。组长打开看板即知谁动没动。

**每个 PR 必须过四关（guard + 模板已替你卡前三道）：**
- [ ] 从 `develop` 拉分支，不直推 develop/main
- [ ] 标题符合 `<类型>(<范围>): <描述>`（如 `feat(mp): 打卡页支持强度滑块`）
- [ ] 描述含 `Closes #编号`
- [ ] 提交前勾 DoD 自查（可演示 / 数据正确 / 异常边界 / 复核人独立复现）
