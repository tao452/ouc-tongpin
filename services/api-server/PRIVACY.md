# 匿名与日志脱敏交接

对应 US-25（#26）。本次提供可复用工具和控制台日志保护，业务接入仍须 M5 配合完成。

## 已实现

- `AnonymousIdGenerator.generate(internalUserId, purpose)` 使用 HMAC-SHA256。
  同一密钥、同一场景及同一内部用户 ID 生成稳定别名；不同场景隔离。
  密钥通过 `ANON_ID_SECRET` 注入，至少 32 字节；无配置/弱密钥调用会失败，不回退到明文或普通哈希。
- 输出 `anon_v1_` 加 URL 安全编码；密钥不入库、不写日志。修改密钥会改变别名，迁移需单独设计。
- `LogRedactor` 掩盖 8–20 位连续数字、常见邮箱、具名学号和凭证值。
  Logback 将整个控制台输出（含异常堆栈和参数格式化结果）放入脱敏转换器。
- 配置数据库和 Redis 时从环境变量读取密码，移除原来的源码明文默认密码。

## 业务侧尚未完成

合成 PII 工具基线与人工复核说明已独立准备，见 `docs/qa/pii-baseline/README.md`。
该基线只验证离线文本规则，不代替下面的真实身份、授权与业务数据验收。

2026-11-09 回归已接入树洞 HMAC 马甲与安全响应 DTO；公开响应移除了内部 userId 和数据库标志，
实名响应只展示昵称。内容表目前仍保留内部 user_id，控制器仍使用 demo 用户 1。
可信 JWT 身份、映射分表与权限控制、真实业务 PII 扫描仍需 M5/M1 协同，不能据此宣称全部隐私验收完成。
M5 接入时需满足：

1. 从已验证 JWT 取得内部随机用户 ID，禁止接受客户端传来的身份；禁止用学号/手机号作生成输入。
2. 身份映射置于独立且受访问控制的表；匿名内容表只存别名，不返回内部 ID 或映射关系。
3. 账号与学校身份信息按必要范围采集与加密保存，限定查询权限、保留期限和删除流程。
4. 禁止记录请求体、认证凭证及身份字段；正则脱敏只作补充，无法识别任意格式的姓名、地址或自由文本隐私。
5. 新增文件、JSON 或第三方日志 appender 时同步加脱敏；当前配置只覆盖控制台。
6. 真实身份持久化完成后，由 M1 执行 PII 扫描并留存结果，复核越权查询和匿名接口响应。

`mvn -B -q verify` 执行 HMAC 稳定性、场景隔离、密钥校验和真实 Logback 输出测试。
