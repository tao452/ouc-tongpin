## 匿名规则与存储

`AnonymousIdGenerator.generate(internalUserId, purpose)` 使用 HMAC-SHA256。
同一密钥、场景和内部用户 ID 生成稳定别名，不同用户及场景隔离。密钥通过 `ANON_ID_SECRET` 注入，
至少 32 字节；缺失或过短时调用失败，不回退到明文、可枚举普通哈希或临时随机值。
输出为 `anon_v1_` 加 43 字符 URL 安全编码。密钥不入库、不写日志；轮换密钥须另行规划别名迁移。

新库的 `treehole_post` 只存别名、内容及帖子元数据，没有 `user_id` 列。
私有 `treehole_identity` 表按 `post_id` 保存内部 `user_id`；内容与映射在同一数据库事务中写入。
映射失败或 Redis 调用抛错时，两张表的写入一起回滚。匿名响应完全不读身份映射；
实名响应通过内部映射读取昵称，映射缺失时显示“用户”。24 小时焚毁处理同时删除私有身份映射并清除
原来的可关联别名，避免内容销毁后仍保留身份关联；哈希留档不带身份映射。公开接口始终返回 `PostResponse`，
没有身份映射查询接口。私有实体禁止输出身份字段到 JSON，并覆盖 `toString()` 以避免意外日志泄露。

后端账号保留必要的业务 DML 权限，移除 DDL；新增只读角色仅访问公开投影，不能查询身份表。
已有环境须由部署管理员执行权限脚本，并继续限制备份和导出；普通前端／报表不得持有后端账号。

## 日志脱敏

Logback 将整个控制台输出（含格式化参数和异常堆栈）交给 `LogRedactor`。
规则覆盖 8–20 位连续数字、常见邮箱、具名学号，以及 authorization、access/refresh token、
password、client secret、API key、openid、session key 等大小写及常见驼峰/下划线字段。
带转义引号或换行的带引号值也整体替换；相似但无关的字段如 `notsecret` 保留。
数据库与 Redis 密码从环境变量读取。

调用方仍应避免记录请求体、凭证和身份字段。正则无法识别任意格式姓名、地址和自由文本隐私；
当前配置覆盖控制台，新增文件、JSON 或第三方日志 appender 时必须同步接入脱敏转换。

## 既有数据库升级

新空库直接使用 `infra/db/init/01-schema.sql`。已有数据卷不能靠重跑初始化脚本升级，
也不应删除数据卷。M5 在备份并停止 API 写入及定时任务后，使用 MySQL 8 客户端执行
`infra/db/migrations/20261115-treehole-identity-separation.sql`，明确选择授权的数据库。
密码通过安全的客户端配置或交互输入提供，不写进 SQL、命令行或 QA 报告。

脚本先检查未焚毁帖子的内部 ID 与当前 HMAC 别名格式，再将仍需保留的旧关联复制到私有表并逐条核对，最后移除内容表的
`user_id` 列；不输出身份明细。旧别名、冲突映射或丢失关联会导致失败，旧字段和记录保留，交由负责人处理。
旧格式别名需要先通过配置了相同密钥的应用完成经评审的 HMAC 回填，不在 SQL 中传递密钥。
MySQL DDL 隐式提交，最终 ALTER 若失败，已复制映射与旧字段同时保留，可排错后重跑。
上线前应在隔离库演练迁移和备份恢复；本次没有执行任何共享数据库升级。
